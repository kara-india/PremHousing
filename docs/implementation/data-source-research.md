# PREM data-source research

**Reviewed:** 2026-11-23
**Scope:** authorized property inventory, MahaRERA checks, licensed property feeds, and mapping / points of interest (POIs).
**Status:** desk research; no vendor contract, legal opinion, API integration, bulk download, or automated scrape has been performed.

## Recommendation

For an MVP, build inventory from broker/owner submissions with explicit permission to publish each listing and its media. Keep the contributor, permission evidence, source URL, last-confirmed date, and takedown status with the listing. Use MahaRERA as a human-verifiable official reference for project/promoter/agent status and link users to the Authority record; do not bulk copy its website into PREM absent explicit written reuse permission or an approved data interface. Ask licensed feed providers for written terms and a quote before ingesting any data. For maps, start with a small no-map workflow or a hosted commercial provider after cost/terms approval. Do not use the OpenStreetMap Foundation's public tile/geocoder servers as production infrastructure; consider OSM data with a compliant commercial tile/geocoder host or self-hosting if PREM accepts ODbL operational obligations. Do not use Google Maps-derived place data as a durable POI database or combine Google content with non-Google maps.

This recommendation prioritizes traceable listing rights and avoids making unsupported claims that a regulatory record proves a unit is available, that an API response grants republication rights, or that a public map service is an SLA-backed commercial feed.

## Official evidence

- [Real Estate (Regulation and Development) Act, 2016, section 34](https://www.indiacode.nic.in/bitstream/123456789/5363/1/the_real_estate_%28regulation_%26_development%29_act%2C_2016.pdf) requires the Authority to publish records for public viewing. This is evidence of public access, not a general republication license.
- [Maharashtra RERA Rules, rule 20](https://upload.indiacode.nic.in/showfile?actid=AC_MH_166_1465_00008_00008_1652266849297&filename=5._rule_21.04.2017.pdf&type=rule) addresses website publication of project disclosures and states the information is to be updated quarterly.
- [MahaRERA Terms and Conditions](https://maharera.php-staging.com/terms-conditions) warns users to verify ambiguity with the concerned department / other sources and says site data should not be interpreted as a statement of law. The accessible terms page was hosted on the Authority's staging domain when reviewed; confirm the current production site's terms before automated use.
- [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/) and [Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/) define production service limits, attribution, and request rules. [OSM Foundation attribution guidance](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines) describes ODbL notices and map attribution.
- [Google Places policies](https://developers.google.com/maps/documentation/places/web-service/policies) state caching, scraping, attribution, and derived-content restrictions; [Google Maps Platform service-specific terms](https://cloud.google.com/maps-platform/terms/maps-service-terms) specify geocoding cache and non-Google map restrictions. [Google India pricing](https://developers.google.com/maps/billing-and-pricing/pricing-india) and [India billing FAQ](https://developers.google.com/maps/billing-and-pricing/india) contain prices and India billing rules.
- [Mapbox pricing](https://www.mapbox.com/pricing) displays usage tiers and the real-estate commercial license requirement. Its normal self-service price should not be treated as a complete commercial real-estate quote.

## Data controls to build into PREM

For every listing, persist: contributor identity and authority, permission timestamp/version, source classification, canonical source reference, media rights status, submitted-at, last confirmed-at, verified-by/verified-at/basis, and takedown/expiry state. The UI should distinguish “MahaRERA record checked on [date]” from PREM-confirmed unit availability. Separate map provider content from PREM-originated listing data and record attribution requirements at dataset/provider level. Avoid joining restricted Google content into a reusable PREM POI database. Make source deletion possible by vendor, source ID, or license expiry.

## Decisions still needed

1. Confirm whether launch listings will be submitted only by PREM-approved brokers/owners, and who is accountable for media rights and availability reconfirmation.
2. Define pilot geography and expected monthly listing/map/geocoding volumes before vendor quotes can be compared.
3. Decide whether ODbL share-alike is acceptable for any OSM-derived POI database; if not, use a separately licensed provider or PREM-owned/manual POI data.
4. If automated MahaRERA import is required, request a written data-access and redistribution position from the Authority; do not infer one from public website access.
5. Obtain at least two licensed-feed proposals with reuse and termination clauses before adding feed-specific schema.
